# Pukumo Asset Studio v1.3

既存シームレスチェッカーを維持し、販売準備を端末内で行う静的Webアプリです。画像処理に生成AI・有料API・サーバー処理・外部ライブラリは不要です。文字透かしはGoogle Fonts CSS APIからフォントを取得します（APIキー不要）。

## 起動

このフォルダをHTTPサーバーで配信します。Pythonがある場合：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8765/` を開きます。HTMLのダブルクリック（file URL）はブラウザごとに保存領域の挙動が異なるため、検証対象外です。

GitHub Pagesへ反映する場合に必要なファイルは、同じ階層の次の5つです。今回の作業では公開していません。

- index.html
- core.js
- studio.js
- studio.css
- watermark.js

`tests/` は開発用です。公開サイトへ配置する必要はありません。

## 文字ウォーターマーク（v1.3）

「紹介画像・透かし・READMEの共通設定」→「ウォーターマーク」で設定します。

- 日本語：Noto Sans JP／Noto Serif JP／Zen Maru Gothic。
- 英語：Montserrat／Lora／Dancing Script。日本語を含む場合、その文字は端末の代替書体を使用します。
- 各書体の標準400／太字700、文字・サイズ・色・回転・文字間隔。
- 中央・四隅・全面繰り返し、外側余白・繰り返し間隔。
- **文字透かしの透明度は0%で不透明、100%で完全透明**です。
- 読み込みが終わってから描画します。失敗時は通知して代替フォントを固定使用します。「フォントを再読み込み」で再試行できます。
- 画像を投入すると「確認」で選んだ画像に透かしを合成したプレビューを表示します。画像なしでは2色の確認用背景です。
- 「この見本をPNGで保存」は表示中の見本を出力します。一括生成では対象全画像へ適用します。
- 原本と透かしなしpreview.pngを維持します。生成結果画面には透かし入りの紹介画像を優先表示します。
- 文字の設定はlocalStorageへ即時保存し、JSONバックアップにも含みます。フォントファイルは保存ZIPへ含めません。
- 既存のPNG透かしも「方式」で選択できます。以前のPNG登録があり新設定がない場合はPNG方式を引き継ぎます。PNG方式の「不透明度」は従来どおり高いほど濃くなります。

フォント通信先はfonts.googleapis.comとfonts.gstatic.comに限定しています。CSS APIのURLに入力文字や画像を含めません。画像の読み込み、プレビュー、PNG合成はブラウザ内で実行します。SIL Open Font Licenseの確認結果はFONT-LICENSES.mdを参照してください。

## 使い方

1. 「紹介画像・透かし・READMEの共通設定」を開き、自分で用意したREADME本文を登録し、文字透かしを設定します。PNG方式も利用できます。
2. 画像、フォルダ、ZIPを読み込みます。対応ブラウザではフォルダのドロップも可能です。
3. 既存チェッカーの一覧、3×3タイル、拡大表示で確認します。端一致は自然なシームレス性を保証しません。
4. 商品名、必要ならカテゴリ・色名・pCloud保存先を入力します。通常イラストは検査対象外モードを選びます。
5. 「販売準備ファイルを一括生成」を押します。2つのZIPリンクからそれぞれ保存します。
6. 商品一覧から複数商品を選択し、CSVを出力します。Notionへの取り込み後に登録済みに変更します。

同じ商品を再生成する場合は、一覧の「再加工」を選んでから原本を投入します。別の商品は「別の商品として作成」で切り替えます。再加工は同一IDの情報を更新し、登録済みの状態を維持します。CSVの再出力は重複警告を表示し、仕様に従いCSV出力済みに変更します。

## 出力

販売用ZIPには、原本のバイト列を変更せず改名した画像と、UTF-8のREADME.txtのみを入れます。形式判定は拡張子ではなく画像ヘッダーで行い、JPEGの出力拡張子はjpgに統一します。PNGへの再エンコードは紹介画像・見本のみです。

管理用ZIPにはpreview.png、manifest.json、inspection.jsonを入れます。透かし登録時はpreview_watermarked.pngとwatermarked/内の個別見本も加えます。透かし未登録ではこれらを省略し、警告します。

ZIPは標準ZIPの無圧縮方式で生成します。圧縮によるサイズ削減はしません。生成後は全項目の名前、サイズ、CRC、原本とのバイト一致を読み直して検査します。

1〜5枚の自動配置は縦帯、6枚以上はグリッドです。グリッドは行に入る画像数に比例して行高を割り当て、数学的に全画像の面積を均等にします。実際のピクセル境界は同じ座標を整数へ丸め、隙間を防ぎます。そのため、割り切れない枚数では1px程度の丸め差があります。切り抜き位置は全画像共通です。

ファイル名はNFKC正規化し、禁止文字・空白を置換します。商品名と色名はそれぞれUTF-8で80バイト以内へ短縮し、OSの長いファイル名の問題を抑えます。元の商品名は管理情報で保持します。

## 保存とバックアップ

IndexedDB `pukumo-asset-studio` に共通設定・透かしPNG・商品情報・CSV出力履歴・採番カウンターを保存します。原本画像と生成ZIPは保存しません。

保存領域はブラウザ・端末・配信元URLごとに独立します。localhostとGitHub Pagesも別です。JSONバックアップで移行してください。同じIDは既存商品を保持してスキップし、結果を表示します。共通設定は、保存領域が空の場合、または「共通設定も復元する」を明示的に選んだ場合に復元します。

商品IDは保存領域内で一意な連番です。削除したIDは再利用しません。複数端末で独立に採番すると同じIDが発生し得るため、運用の主となる保存領域を決めてください。復元時の衝突は自動上書きしません。

ブラウザのデータ消去に備え、定期的にJSONを書き出してください。pCloudは保存先情報の記録のみです。アップロード、Notion API、Firebase、クラウド同期はありません。

## 構成と拡張

- index.html：既存の検査・タイル・拡大表示。接続用アダプターのみ追加。
- core.js：命名、均等配置、CSV、ZIP生成・検証。
- studio.js：Canvas加工、透かし、IndexedDB、商品一覧・バックアップ。
- studio.css：追加画面専用のスタイル。

将来の使用イメージ合成は、原本Blobの配列を読み取り、派生Blobの配列を返すローカル処理として分離する契約を用意しています。テンプレート合成・プラグインローダーの本実装は今回含めません。

## 開発テスト

文字透かしの実ブラウザテストは `tests/watermark.html` で実行します。Google Fontsの実取得と失敗時の代替、全配置、透明度、画素一致、localStorage復元を検証します。

Node.jsの標準機能だけで純粋関数の検証ができます：

```sh
node --test tests/core.test.cjs
```

HTTP配信後、専用のテスト用ブラウザ／配信元で `tests/harness.html` と `tests/extra.html` を開き、各テスト実行ボタンを押します。テスト商品・設定をその配信元のIndexedDBへ保存します。実際の商品を管理する保存領域では実行しないでください。

`tests/browser.test.cjs` はPlaywright＋Chromeが利用できる環境向けの追加自動化です。Playwrightは開発時のみ必要で、アプリには含まれません。この実行環境ではChromeのプロセス起動が制限されているため、ブラウザ内テストで検証しました。

検証結果・未検証環境は同梱のTEST-REPORT.mdを参照してください。
